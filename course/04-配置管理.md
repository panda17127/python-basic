# 第 4 课:配置管理

## 目标

配置住文件里,不住人的记忆里;秘密不进代码。

## 两个真实痛点

1. 每次启动都敲 `--port 8001`——配置应该有默认的家
2. 数据库密码、API 密钥写死在代码里 = 随 git 提交泄露

## 核心概念:BaseSettings = 会"自己找值"的 Pydantic 模型

语法和普通模型一样,只换了父类。数据不再手动传,而是启动时**按优先级链自动收集**:

```
环境变量(临时手动指定)  >  .env 文件(本机偏好)  >  代码里的默认值(出厂设置)
```

类比手机:出厂设置(默认值)→ 你的偏好设置(.env)→ 临时飞行模式(环境变量),后者总能覆盖前者。

## 三个文件

```python
# app/config.py
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env")   # 找值时顺带读 .env

    app_name: str = "good-finds-server"
    version: str = "1.3.0"
    host: str = "127.0.0.1"
    port: int = 8001
    debug: bool = True
    database_url: str = "sqlite:///./lianxi.db"

settings = Settings()   # 单例:全项目只造一次,处处 import 这个实例
```

```
# .env(项目根目录,已被 .gitignore 排除)
PORT=8001
DEBUG=true
```

```python
# run.py —— 真正的启动入口
import uvicorn

from app import models  # noqa: F401 —— 导入触发表注册(第 5 课)
from app.config import settings
from app.database import Base, engine

if __name__ == "__main__":
    Base.metadata.create_all(engine)
    uvicorn.run("app.main:app", host=settings.host, port=settings.port, reload=settings.debug)
```

从此启动只要 `python run.py`,不再需要 uvicorn 命令行参数。改 `.env` 的 PORT,一行代码不动,服务搬家。

## 深讲 1:类 vs 实例(图纸 vs 实物)

`Settings` 是**类**(图纸,大写开头);`settings = Settings()` 是**实例**(按图纸造出的实物,小写开头)。只定义类不实例化 = 只画图不施工,`from app.config import settings` 会报 `cannot import name 'settings'`——房间找对了,但人不在。

## 深讲 2:`if __name__ == "__main__"` 守卫

- 亲手运行 `python run.py` → 文件内 `__name__` 为 `"__main__"` → 守卫内代码执行
- 文件被 import(包括被 **Windows 子进程重新导入**)→ `__name__` 为模块名 → 守卫内代码**跳过**

为什么必须加:Windows 创建子进程用 spawn 方式——**子进程会重新 import 你的主文件**。不设守卫,`uvicorn.run` 在子进程里再执行一遍,子进程再想 spawn 孙进程时被 Python 拦下:

```
RuntimeError: An attempt has been made to start a new process
before the current process has finished its bootstrapping phase...
```

**现场证据**:启动横幅打了两遍(两个 reloader 进程号)。守卫的哲学:`import` 放外面(读图纸无副作用),只有"点火"锁进守卫。

## 深讲 3:导入串 `"<module>:<attribute>"`

给 `uvicorn.run` 传字符串,它当作"指路牌":`"app.main:app"` = app/main.py 里的 app 变量(点 = 斜杠,冒号 = "里面的那个")。

为什么开 reload 就必须传串不能传对象:重载要不断杀旧进程起新进程,活对象无法跨进程传递,字符串这个"地址"可以——新进程拿着地址自己去 import。

**注意区分**:`settings.app_name` 是应用的名字(标题),`"app.main:app"` 是应用的地址——传成前者会报 `must be in format "<module>:<attribute>"`。

## 生产环境的密码放哪(标准答案)

**环境变量**那一环。`.env` 是文件,会随误提交/备份/镜像泄露;环境变量住在进程内存里不落盘,部署平台(Docker/云)有专门的密钥注入机制。口诀:**默认值给安全值,.env 给本机,真秘密给环境变量。**

## 附:虚拟环境(.venv)

一台机器多个项目,依赖版本会打架(A 要 fastapi 0.143、B 要 0.162)——venv 给每个项目独立的包世界。学习期单项目可以不用,但要知道:

```powershell
python -m venv .venv          # 建
.venv\Scripts\Activate.ps1    # 激活(提示符出现 (.venv))
pip install -r requirements.txt
```

装包必须装进"运行时用的那个世界";`& .venv\Scripts\python.exe -m pip install X` 指名道姓,永不装错。VSCode 选错/选了已删除的解释器会导致"无法解析导入"黄线——那是 Pylance(静态分析)在死人坟前找包,与运行无关。
