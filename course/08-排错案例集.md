# 附:排错案例集(11 个真实报错)

本课程实际踩过的每一个坑。复习时先看"报错关键句",想想自己的诊断思路,再看答案。

## 案例 1:`can't open file 'run.py': No such file or directory`

- **根因**:文件根本没建。报错有时不是"写错了",是"缺东西"
- **教训**:看报错第一件事——确认它抱怨的对象是否存在

## 案例 2:`ImportError: cannot import name 'settings' from 'app.config'`

- **根因**:config.py 里只有**类** `Settings`(图纸),没有**实例** `settings`(实物)。没人 `Settings()`,自然 import 不到
- **读法**:`ModuleNotFoundError` = 整个房间找不到(import 路径错);`cannot import name` = 房间对了人不在(名字错/没定义)
- **修复**:config.py 末尾 `settings = Settings()`(单例),全项目 import 这个实例

## 案例 3:`RuntimeError: ... bootstrapping phase ... if __name__ == '__main__'`

- **根因**:Windows 子进程用 spawn 创建,会**重新 import 主文件**;没有守卫,`uvicorn.run` 在子进程里再执行,孙进程在引导期被拦
- **现场证据**:启动横幅打了两遍(两个 reloader 进程号)
- **修复**:`if __name__ == "__main__":` 包住 `uvicorn.run`。报错最后一段直接写了答案——**先读尾**

## 案例 4:`Import string "good-finds-server" must be in format "<module>:<attribute>"`

- **根因**:把 `settings.app_name`(应用的**名字**)传给了需要**地址**的地方。uvicorn 要的导入串格式是 `"app.main:app"`(模块:变量)
- **延伸**:为什么必须传串——reload 模式跨进程重建应用,活对象传不过去,字符串地址可以

## 案例 5:POST 成功了,数据库却没数据

- **根因**:路由路径 `"api/messages"` 少了开头的 `/`,请求 404,**根本没进到数据库那一步**。证据链:全盘只有一个 db 文件、大小和建表时一模一样(8192 字节)→ 没有任何 INSERT 到达过
- **分诊口诀**:404 没进门(路由)/ 422 被门卫拦(数据校验)/ 500 进门摔了(代码错)
- **教训**:"数据没进库"要沿链路倒查:响应码 → 路由匹配 → handler → session/commit → 文件

## 案例 6(测试):`sqlite3.OperationalError: no such table: message`

- **根因**:内存库 `sqlite://` 的库**住在一条连接里**,连接关闭库就蒸发。create_all 建的表随连接 A 消失,请求拿到的是连接 B(空房)
- **修复**:`poolclass=StaticPool`,全体共用一条连接

## 案例 7(编辑器):无法解析导入 "pydantic_settings"(黄线)

- **根因**:VSCode 的 Pylance(静态分析)按**选中的解释器**找包,而它还指着已删除的 .venv。终端能跑,编辑器报红
- **修复**:Ctrl+Shift+P → Python: Select Interpreter → 选系统 Python 3.10
- **概念**:运行时和静态分析是两套系统;**波浪线是警告不是判决**,以运行结果为准

## 案例 8:`pytest : 无法将"pytest"项识别为 cmdlet...`

- **根因**:pytest 的命令行入口在 Python 的 Scripts 目录,PATH 里没有它
- **修复**:`python -m pytest`。**`-m` 惯用法**(pip 同理):让当前 Python 调自己的模块,指名道姓永不出错

## 案例 9:`create_all` 静默失败:db 文件 0 字节,一张表都没有

- **根因**:run.py 缺 `from app import models`——表在类被定义时注册进 `Base.metadata`,类定义靠 import 触发。没 import,create_all **完美地什么都没建**,不报错不警告
- **取证**:`sqlite3.connect()` 本身会创建空文件,所以"文件在 ≠ 表在";真凭据是 `sqlite_master` 里的表名
- **教训**:静默的成功比响亮的失败更危险;验证要验到内容,不能只验存在

## 案例 10:端口被占 / 孤儿进程

- **场景 A**:8000 被本项目旧实例占用(没开 reload,跑旧代码)→ 查明后要么杀要么换端口
- **场景 B**:`--reload` 是 1 父 + 多子的进程树,只杀父进程留下孤儿子进程继续占端口;甚至出现"连接表说 PID 在监听、系统说该 PID 不存在"的僵尸记录
- **工具**:`Get-NetTCPConnection -LocalPort N -State Listen` 查占用;`taskkill /PID n /T /F` 杀整棵树(/T = tree);VSCode 里 Ctrl+C 是首选

## 案例 11(编辑器提示):未存取 "models"

- **根因**:side-effect import——`from app import models` 的价值在"导入触发注册"这个动作本身,变量确实没被用到
- **修复**:`# noqa: F401` 告诉检查器这行没白写。Hint 级别,无害

## 排错方法论(比案例本身更值钱)

1. **先读报错最后一段**——很多报错自带答案(案例 3)
2. **响应码分诊**——404/422/500 各查各的方向(案例 5)
3. **沿链路倒查**——现象在下游(库里没数据),病根常在上游(没进门)
4. **用证据不用感觉**——文件大小、进程号、sqlite_master、横幅打几遍,都是证词
5. **区分两套世界**——运行时 vs 静态分析(案例 7)、系统 Python vs venv(装包要装对世界)
6. **`-m` 惯用法**——命令找不到、pip 装错地方,一个 `-m` 全解决(案例 8)
